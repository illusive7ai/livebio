A GitHub profile README that keeps itself up to date. Open source, no sign-in, nothing stored.

### [Try it: illusive7ai.github.io/livebio](https://illusive7ai.github.io/livebio/)

Type your GitHub username, pick a design, make it yours, and export. A small GitHub Action in your own profile repository then refreshes your stats every day, so your profile never goes stale and never depends on someone else's server.

> **Status: early.** The builder, a Templates gallery, a Studio for restyling designs (colour, fonts, text size, a time-lapse city, a side-by-side compare view), GitHub Wrapped, a README linter, a Chrome extension and the Action all work, with 100 templates. Every one carries a live contribution city and an automated snake or chess game (the two designs that already are a city or a snake carry the other half). See the [roadmap](#roadmap).

## What you get

- **100 designs**, from a calm recruiter page to a lava lamp, a punch card and a tarot spread. Every one carries a live contribution city and a chess game or snake that plays itself.
- **A Studio** to make any design yours: its colour, nine typefaces, text colour and size, a time-lapse city and which game plays. Set two designs side by side to choose between them, and keep favourites.
- **GitHub Wrapped**: your last twelve months told from your real numbers, as slides and a card to share.
- **A README linter** that finds what is wrong with any README and writes a corrected copy.
- **A Chrome extension** that brings Wrapped and the README checker into GitHub itself.
- **Two ways to publish**: copy and paste, with pictures drawn live and nothing to upload, or host the files yourself with a daily GitHub Action.
- **No sign-in, no paywall, nothing stored.** Free and open source under the MIT license.

## How it works

1. **Preview.** The builder reads your public GitHub data in the browser, with no login.
2. **Choose and customise.** Pick one of the 100 designs, edit the text, switch sections on or off, and make it yours in the Studio: colour, fonts, text size, a time-lapse city, which game plays. Compare two designs side by side if you cannot decide.
3. **Export.** Download a zip with your `README.md`, a `livebio.yml` config and a workflow file.
4. **Stay fresh.** Put those files in your `username/username` repository. The workflow runs daily, regenerates your images from live data using GitHub's built-in token, and commits the result.

Everything is generated as plain files in your own repository. Images are SVGs, not requests to a hosted service, so they cannot break or hit someone else's rate limit.

## Principles

- **Never invent facts.** If GitHub has no value for a field, the template leaves it out. No made-up job titles, no placeholders.
- **Light and dark.** Designs follow the viewer's GitHub theme, and animations respect "reduce motion".
- **Accessible.** Images get real alt text that describes only what they show.
- **Safe.** Profile text is escaped everywhere, and the preview is sanitised.
- **Tested.** Every design has tests for the numbers it shows, and shared tests run all of them against empty, one-day, very quiet and hostile profiles, so a design never leaves a blank page or breaks out of its picture.

## Privacy

- **What leaves your browser:** only the request for your public GitHub data, and, if you publish by copy and paste, the picture requests your profile makes to the livebio server.
- **The README linter** and **GitHub Wrapped** work on your own device. The text you paste is never uploaded, and Wrapped is calculated in the browser from the public data it was given.
- **Favourites, recent designs and saved designs** are kept in your own browser. There are no accounts, no cookies and no tracking.
- **The picture server** keeps a one-hour copy of public GitHub data and nothing about who looked.
- **The Chrome extension** checks a README inside your browser and sends nothing about it. It contacts the livebio server only when you ask for someone's Wrapped, and then only to say which public username you asked about. It never loads a profile on its own.

## Copy and paste, with live pictures

The quickest way: pick a design on the site, press **Copy README**, and paste it into the README of your profile repository (a public repository named like your username). That is all. There is nothing to upload and nothing to set up.

The README holds no image files. Each picture is an address on the livebio server, which draws it from your public GitHub data when your profile is viewed, so your numbers, contribution city and chess game stay current by themselves. A picture is refreshed about once an hour.

- **What is kept:** only a one-hour copy of public GitHub data, so a busy profile does not use up GitHub's limits. No accounts, no cookies, nothing about who looked.
- **What it depends on:** the livebio server being up. If you would rather not depend on it, choose **Host the files myself** on the site (or use the Action below). Those files are yours and need no server.
- **Running your own server:** the picture server is the Cloudflare Worker in [workers/contributions](workers/contributions). Deploy it with your own token and point the site's `VITE_CONTRIBUTIONS_URL` at it.

## Use the Action

In your profile repository (named the same as your username), add `livebio.yml`:

```yaml
username: your-username
template: showcase   # see the Templates page for every id, for example showcase, launchpad, city, frontend, backend, ossproof or minimal
theme: auto
motion: true
credit: true
blocks: [stats, activity, languages, projects, city, game]
text:
  headline: Security researcher
custom:              # optional: make any design your own
  hue: 200           # accent colour, 0-359 (default: taken from your profile picture)
  look: blueprint    # look of the city and game panels: aurora, sunrise, night, space, arcade, chalk, editor, blueprint, paper, terminal, glow or plain
  companion: chess   # which game plays under the card: snake, chess or none
  font: serif        # one typeface for all text: sans, serif, mono, rounded, humanist, classic, typewriter, handwriting or impact
  textColor: "#7ee787"  # one colour for all text, written as #rrggbb
  textSize: 110      # text size as a percentage of the design's own, 80 to 130
  timelapse: true    # draw the contribution city as a time-lapse that grows week by week
```

and `.github/workflows/livebio.yml`:

```yaml
name: livebio
on:
  schedule:
    - cron: "17 3 * * *"
  workflow_dispatch:
permissions:
  contents: write
jobs:
  update:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: illusive7ai/livebio@v0.1.3
        with:
          token: ${{ secrets.GITHUB_TOKEN }}
      - run: |
          git config user.name "livebio[bot]"
          git config user.email "livebio[bot]@users.noreply.github.com"
          git add -A
          git diff --cached --quiet || (git commit -m "Update profile README" && git push)
```

If your README already contains `<!-- livebio:start -->` and `<!-- livebio:end -->`, only the text between them is replaced, so the rest of your README is left alone.

The builder generates both files for you. The Action is the "host the files myself" option: it writes the pictures into your repository every day, so your profile never depends on a server.

## Activity: contribution graph and streaks

The `activity` section shows your contribution graph and streaks. GitHub only shares that data with a token, so:

- **In your profile**, the Action reads it with the workflow's built-in `GITHUB_TOKEN`. If it cannot, it prints a warning and leaves the section out, and everything else still updates. In that case, create a token with no scopes, save it as a repository secret and pass it as the `token` input instead.
- **In the builder's preview**, a small [edge function](workers/contributions) supplies the same data. It is optional. Without it the preview just has no activity section, and your profile still gets one.

Streaks are worked out from the calendar itself. A streak is current if it includes today, or yesterday when today has no activity yet. The longest streak is the longest within the past year of data.

## Templates and the Studio

The site has a **Templates** page with every design in one grid, and a **Studio** where you start from any design and change:

- its **accent colour**, the **look** of its city and game panels, and which **game** plays;
- its **city**, as the finished year or a **time-lapse** that grows week by week with a running total of real counts;
- its **text**: nine typefaces, one colour for all words (with a readability check against GitHub's dark and light pages) and a size from 80% to 130%. GitHub cannot load web fonts, so each typeface is a stack of fonts that already ship with the reader's device and looks a little different from one device to the next.

The Studio can also set **two designs side by side** with your own profile in them, then keep the one you like. Press the **heart** on a design to keep it among your favourites; the designs you used last are listed too. Favourites, recent designs and saved designs stay in your browser only, with no sign-in. **Export livebio.yml** from the Studio to use a design on GitHub; the `custom` settings above are what it writes. The Studio changes and combines the existing designs. It does not edit their layouts.

## GitHub Wrapped

The **Wrapped** tab tells your last twelve months from your real contribution calendar and public profile: total contributions, active days, streaks and your longest quiet stretch, your busiest day, month and weekday, how much landed on weekends, your best week, languages and stars. A label such as "Weekend warrior" appears only when your numbers earn it, and it shows which numbers did. It never invents a time of day or a comparison with an earlier year, because GitHub's calendar has neither. It ends with a card you can download as PNG or SVG. Everything is worked out in your browser.

## README linter

The **README linter** tab checks a README you paste, open as a file, or load from a profile by username, and writes a corrected copy. It covers headings, tables, lists and code blocks that do not render; broken, insecure or local-only links; images without alt text; HTML that GitHub removes or leaves open; markdown that sits inside HTML and shows as plain text; leaked tokens and keys; leftover template text; pictures that depend on someone else's free server; spelling and product names. Each issue says whether the corrected version already fixes it or whether only you can, and the **Changes** tab shows exactly what was altered. Nothing you paste leaves your browser.

## Chrome extension

**livebio for GitHub** brings Wrapped and the README checker into GitHub itself. It works in Chrome, Edge, Brave and other Chromium browsers.

- **Popup:** click the icon, type any username, and get their Wrapped card and numbers.
- **Profile helper:** on a github.com profile, a small pill offers that person's Wrapped, only when you press it.
- **README checker:** on a README, and in GitHub's editor, the pill checks the text and offers a corrected copy to copy, download or put straight into the editor. It runs in your browser.
- **Right-click:** on a link to a profile or repository, or a selected username, open their Wrapped card.

### Install it

1. **[Download the zip](https://illusive7ai.github.io/livebio/livebio-extension.zip)** (about 70 KB) and unzip it somewhere you will keep it.
2. Open `chrome://extensions` (`edge://extensions` in Edge, `brave://extensions` in Brave) and switch on **Developer mode**.
3. Press **Load unpacked** and choose the unzipped folder, the one that holds `manifest.json`.

It is loaded unpacked for now, not from the Chrome Web Store. The [Extension tab](https://illusive7ai.github.io/livebio/#/extension) of the website has the same steps and explains every permission it asks for. It asks for two permissions plus access to github.com, raw files on GitHub and the livebio server, has no accounts or tracking, and never sends the text of a README anywhere. To build it yourself, see [apps/extension](apps/extension/README.md).

## Reviews on the website

The home page shows reviews from real users, and says plainly when there are none yet. To add one, someone submits the **Share your experience** form (`.github/ISSUE_TEMPLATE/review.yml`) and ticks the box that agrees to have it shown. The site reads these issues itself, through the contribution service (`/reviews`), and caches them for ten minutes. A review from any GitHub user appears on its own, with no approval step, once the cache refreshes. Only reviews written with the form, with a rating, some text and the box ticked, are shown, and each is shown as plain text next to the GitHub username that opened the issue. Reviews from bots, and reviews that contain a web address (which is how advertising gets onto a page), are left out. To take a review down, a maintainer adds the `hidden` label to its issue, or closes the issue as spam; the label takes effect within ten minutes. The same service also reports the repository's star count (`/stars`), which the home page shows next to its WhatsApp, Telegram and copy-link share buttons. `apps/web/src/data/testimonials.ts` is only a fallback for when the service cannot be reached; never add a review there that was not submitted by the person it names.

## The credit line

By default the generated README ends with a small glitching "livebio by illusivehacks" credit. It is an image, because a profile README cannot run CSS, and it links to this project. It helps the project reach people. You can switch it off with one checkbox in the builder, or with `credit: false` in `livebio.yml`.

## Develop

Requires Node 20 or newer.

```
npm install
npm run dev        # the builder at http://localhost:5173
npm test           # engine tests
npm run typecheck
npm run build
```

To work on the extension, `npm run build -w @livebio/extension` builds it into `apps/extension/dist` for **Load unpacked**, `npm run package -w @livebio/extension` makes the zip the website offers, and `npm test -w @livebio/extension` runs its tests.

| Path | What it is |
|---|---|
| `packages/core` | The engine: GitHub data, the 100 designs (`templates/`), README and SVG rendering, the Studio's fonts and colours, GitHub Wrapped, and the README linter (`linter/`). Shared by the web app and the Action. |
| `apps/web` | The builder. |
| `packages/action` | The GitHub Action. Its bundle in `dist/` is committed, because Actions run it directly. |
| `apps/extension` | The Chrome extension: Wrapped, a profile helper and the README checker inside GitHub. See its [README](apps/extension/README.md). |
| `workers/contributions` | Optional edge function that gives the builder's preview contribution data. |

After changing `packages/core` or `packages/action`, run `npm run build -w @livebio/action` and commit the updated `dist/index.js`.

### Adding a design

A design is a small TypeScript function that draws one SVG from a profile. Copy the closest file in `packages/core/src/templates/` (for example `shop.ts` for a drawn object, or `imagery.ts` for one made from the profile picture), then:

1. Build it with `imageTemplate(id, name, description, tags, svg)`, and give it a test file in `packages/core/src/` for the numbers it shows. The rules: draw only real data, leave out whatever is missing or switched off, escape every piece of text, and say what you are waiting for rather than filling the space.
2. Add it to the list in `templates/index.ts`, with an entry in `LIVE` giving the look of its city and game panels. Each design needs a different look-and-shift pair, and a test checks that.
3. Give it a group in `apps/web/src/lib/catalog.ts`.
4. Run `npm test`. The shared tests will try your design on empty, one-day and hostile profiles for you.

See [CONTRIBUTING.md](CONTRIBUTING.md) for the rest.
